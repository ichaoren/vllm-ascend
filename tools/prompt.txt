The Grouped Dot Network (GDN) operator, formally named GroupedMatmulSwigluQuantV2 in the CANN operator library for Huawei Ascend Neural Processing Units (NPUs), is a hardware-optimized fused quantization matrix multiplication kernel exclusively engineered to accelerate the core feed-forward computation within transformer large language models (LLMs) under low-bit MXFP4/W4A4 mixed quantization schemes. Unlike generic unfused matrix multiplication primitives such as aclnnQuantMatmulV5 that handle standalone linear projection layers, the GDN operator integrates four critical computational stages into a single end-to-end hardware pipeline: grouped low-bit weight dequantization, batched input activation quantization, parallel grouped matrix dot product computation for SwiGLU dual-branch feed-forward layers, and fused post-multiplication element-wise SwiGLU non-linear activation with shared MX scale factor compensation. This deep operator fusion eliminates redundant intermediate tensor read-write overhead on NPU Global Memory (GM) and Local Memory (LM), which is the primary performance bottleneck of split, modular quantization implementations in open-source LLM inference frameworks including vLLM-Ascend, TGI-Ascend, and TensorRT-LLM ported for Ascend CANN stacks.
At its core architectural design, GDN targets the canonical SwiGLU feed-forward network block ubiquitous in modern open-weight LLMs such as Qwen series, Llama 3, Mistral, and Yi models, which split the hidden dimension into two parallel linear projection branches—gate projection and value projection—then compute element-wise multiplication of the activated gate branch with the unmodified value branch to produce feed-forward output features. In standard unfused quantization workflows, the inference engine would execute separate quantization and matmul kernels for the gate linear layer and value linear layer sequentially, requiring two full rounds of weight scale loading, activation MX block normalization, matrix multiplication, temporary result storage, and scale inverse compensation before executing the SiLU element-wise activation and element product.
To align with the MXFP4 quantization constraints highlighted in vLLM-Ascend runtime error logs related to aclnnQuantMatmulV5 dimension validation failures, the GDN operator enforces rigid hardware-aligned block partitioning rules for both input activations and compressed 4-bit weight matrices. MX quantization, short for MicroScaling quantization, splits tensor feature dimensions into fixed-size blocks of 64 contiguous elements, with one shared floating-point scale value allocated per block to normalize all 4-bit quantized values inside the block. This block size of 64 is hard-coded into Ascend NPU Vector Compute Unit (VCU) hardware instruction pipelines, as the vector register file width and data movement burst size are optimized for 64-element block granularity. Generic quantization matmul kernels often suffer from shape mismatch runtime errors when tensor channel dimensions are not perfectly divisible by 64, or when tensor parallelism (TP) weight slicing distorts block alignment after single-card weight partitioning. The GDN operator embeds native hardware padding logic inside its kernel implementation to resolve this long-standing compatibility issue. When the K-dimension (feature input channel) of sliced TP weight tensors or batch input activation tensors is not an integer multiple of 64, the operator automatically inserts zero-padding dummy elements to extend the tensor dimension up to the next 64-aligned value during on-chip tiling, generates corresponding padding MX scale values of 1.0 to avoid distorting quantization precision, and masks out padded dummy partial sums during the final reduction stage to ensure mathematical equivalence with the original un-padded transformer feed-forward computation.
The weight storage and dequantization sub-pipeline inside GDN is purpose-built for grouped W4A4 MXFP4 weights used in vLLM-Ascend low-bit inference. Compressed LLM weights are serialized as packed 4-bit unsigned integers stored two values per 8-bit byte, with a separate parallel weight scale tensor storing block-wise MX scaling factors pre-computed during model quantization export. The GDN kernel’s weight load unit retrieves packed weight bytes from GM, unpacks paired 4-bit values into aligned VCU vector registers in a single hardware cycle, and applies block scale dequantization using pre-fetched scale tiles resident in LM cache. For SwiGLU dual-branch feed-forward layers, GDN accepts two distinct grouped weight matrices (gate weight and value weight) as input operands, and schedules parallel dot product computation across both weight groups on independent VCU sub-cores within the same NPU compute tile. Instead of loading the full input activation tensor twice for two separate matmul passes, the operator loads input activation tiles once, performs on-the-fly MX block quantization using per-token activation scale factors, and feeds the quantized activation vector data into both grouped matrix dot product pipelines concurrently.
